Manual · Font Info

Compatibility

Masters can only interpolate if their outlines share a structure. This tab is a font-wide report of every glyph whose masters don't match the default master — what will block a variable font, and what will merely look wrong.

When it appears

The tab is shown when the font has two or more masters. Its report is always live: it updates whenever a glyph's structure, the masters or the axes change, whatever the Auto compatibility check setting is.

Reading the report

  • A summary line counts issues, blockers and warnings for the whole font. “All glyphs are interpolation-compatible.” means there is nothing to fix.
  • Filter with All, Blockers only or Warnings only, and narrow by name with Filter by glyph name….
  • The table has Glyph, Master, Severity and Reason columns — one row per problem, blockers first, then by glyph name. The Master column names the master that differs from the default.

Why structure must match

A variable font stores one set of outlines — the default master — plus, for every other master, a delta for each point. Point n in one master can only move towards point n in another, so every master needs the same contours, the same points in the same order and the same point types. TrueType variations are stored in the gvar table, PostScript ones as CFF2 blend data.

What each reason means

Every non-default master is compared with the default master. Contour, point and component numbers count from 0.

ReasonSeverityMeaning
ContourCountBLOCKERA different number of contours.
PointCountBLOCKERA contour has a different number of points.
SegmentKindBLOCKERA point is a different type — a line where the default has a curve, for example.
ComponentCountBLOCKERA different number of components.
ComponentRefBLOCKERA component points to a different base glyph.
CompositeMixBLOCKERThe glyph is a composite in one master and outlines in another.
PathDirectionWARNINGA contour winds the other way.
StartPointWARNINGA contour starts at a noticeably different point; the distance is shown in units.
ContourOrderWARNINGThe contours appear to be listed in a different order.
MissingMasterLayerWARNINGThe master has no usable layer for this glyph.

Point positions are meant to differ between masters and are not checked; neither are anchors, kerning, features or metrics.

Effect on export

  • Blockers stop variable font and named-instance export. The export error names up to five glyphs and points you to Font Info → Compatibility for the full list.
  • Warnings never block export.
  • Exporting a single static master is not checked.

Fixing issues

This tab reports; the fixes live in the glyph editor. Open the glyph on the master named in the row.

  • The editor inspector's Compatibility section lists each master's issues. Inline Fix buttons — Match structure in this contour, Match start to default, Match direction to default, Match order to default, Match reference to default — apply at once and undo with Ctrl Z / ⌘ Z.
  • Propagate structure from default previews and applies the default master's structure to one master; Propagate to all does every master in one undoable step.
  • The Glyph → Path menu has Correct Path Direction (Ctrl Shift R / ⌘ ⇧ R), Reverse Path Direction, Make Selected Point Start, and Match Contour & Component Order to Default.
  • A different number of contours or components has to be fixed by adding or deleting them by hand; a composite / outline mix by decomposing.

Fix the default master first — the tools never change the default to match another master.

Checking as you edit

Turn on Settings → General → Auto compatibility check (off by default, because it costs time on large fonts) to also see issues in the glyph grid as a colored strip on each affected cell, in the grid inspector, in the editor inspector, and as markers on the canvas. It doesn't change this tab or the export check.
