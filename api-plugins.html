Building plugins

Ink plugins are small web apps. They dock into the workspace as panels, talk to the open font through a JavaScript SDK, and hand heavy work to Python scripts that use the ink module.

How it fits together

Sandboxed iframe, global Ink
postMessage
Ink host

Reads and writes the font database

Python script
import ink
  • A plugin's UI loads into an <iframe sandbox="allow-scripts"> docked in the right (default), left or bottom slot — or runs headless.
  • The host injects a global Ink object. Each call is a message to the host, which routes it into the Rust ink-api crate that reads and writes the open .ink project.
  • Ink.python.run starts a script declared in your manifest inside the scripting environment Ink manages (see Settings → Python), with the ink module already installed.

The manifest

Every plugin is a folder with a plugin.json at its root. Fields are camelCase.

FieldMeaning
id · name · versionRequired. id is lowercase with hyphens; version is semver.
entryRequired. HTML file relative to the plugin folder (a full URL in Developer Mode).
description · authorOptional metadata.
slot"right" (default), "left", "bottom" or "headless".
defaultWidth · minWidth · defaultHeight · minHeightPanel size for side and bottom slots.
activationEventsonStartup (the default), onCommand:<id>, onView:<id>, onGlyphSelect, onEvent:<event>. Panel plugins must include onStartup.
contributesArrays of commands, toolbar, menus, contextMenus, statusBar, tools, inspector, tabs, categories, gridOverlays and keybindings.
python.requiresPython version constraint, e.g. ">=3.12".
python.scriptsMap of script key → relative path. Ink.python.run takes the key, not a path.
python.assetsDownloadable files {id, url, size?, sha256}. sha256 is required for remote assets and is verified.

when clauses on contributions support &&, ||, !, == and != over keys such as glyphEditor.active, editor.mode, editor.hasSelection, glyph.isComposite and font.isBinary.

A panel in twenty lines

<div id="info">Loading…</div> <button id="analyze">Analyze metrics</button> <script> let font; Ink.currentFont().then((f) => { font = f; info.textContent = `${f.familyName} ${f.styleName} · ${f.glyphCount} glyphs`; }); Ink.on('glyph:focused', async ({ glyphName }) => { const glyph = await font.getGlyph(glyphName); const contours = await glyph.getContours(); Ink.overlay.clear(); Ink.overlay.contours(contours, { color: 'rgba(74,67,200,0.5)', width: 1 }); }); analyze.onclick = async () => { const run = Ink.python.run('analyzeMetrics', { limit: 20 }); const { exitCode, data } = await run.result; Ink.ui.alert(`exit ${exitCode}: ${JSON.stringify(data)}`); }; </script>

Talking to Python

Scripts receive context through environment variables — INK_FONT_PATH, INK_PLUGIN_DIR, INK_ASSETS_DIR and INK_ARGS (JSON) — and reply on stdout:

  • __INK_DATA__:<json> is delivered to onData; a payload with "type": "progress" drives a progress bar.
  • __INK_RESULT__:<json> becomes result.data.
  • The ink.ui helpers handle dialogs for you. See the Python reference.

Installing and developing

  • Copy the plugin folder into %APPDATA%\com.intaglio.ink\plugins\ (Windows) or ~/Library/Application Support/com.intaglio.ink/plugins/ (macOS), then open Settings → Plugins, click Reload and Enable it.
  • While developing, turn on Enable Developer Mode and paste a manifest whose entry is your dev server URL, e.g. http://localhost:8080/index.html.
Trust and limits
  • The iframe sandbox keeps a panel away from Ink's own UI, but there is no per-plugin permission system yet: every enabled plugin gets the full API, and its Python scripts run with your user's full access. Only install plugins you trust.
  • One Python script runs per plugin at a time; scripts are stopped after their timeout.
  • Installed plugins can only run scripts inside their own folder. Developer Mode lifts that limit — treat enabling it as a trust decision.
