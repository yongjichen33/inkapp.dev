Features

Write OpenType feature code — substitutions, positioning, classes and language systems — in AFDKO feature syntax, and check that it compiles exactly as it will on export.

Adobe · Feature file syntax ↗ OpenType spec · GSUB ↗ GPOS ↗ GDEF ↗ Feature tags ↗

The block list

On the left, feature code is split into three groups, each with its own +:

ClassesNamed glyph classes such as @UPPERCASE. + opens “New glyph class”.
PrefixesCode at the top of the file: languagesystem lines, standalone lookups, other declarations. + adds one straight away, named __prefix_N__.
FeaturesOne block per feature tag. + opens “New feature”.
  • Hover a row and click its trash icon to delete it; Ink asks first.
  • Blocks marked disabled in an imported .glyphs or UFO source are shown struck through and are left out of compiled fonts.

New feature

  • Pick a feature from the OpenType Feature Tag Registry or type any tag of up to four characters. Suggestions match the tag or its registered name — type “small” to find smcp — and include ss01–ss20 and cv01–cv99.
  • A valid tag that isn't registered is allowed, with a note saying so.
  • If the tag already exists, the dialog offers to open that block instead.

New glyph class

Type a name using letters, digits, ., _ or -; the leading @ is added for you.

Writing code

Each block shows its tag and a type badge. What you type depends on the type:

  • Feature — only the body. Ink adds feature xxxx { … } xxxx;.
  • Class — only the members. Ink wraps them as @name = [ … ];.
  • Prefix — free text, used exactly as written.
# liga — just the body sub f f i by f_f_i; sub f f by f_f; sub f i by fi; sub f l by fl;

The editor has syntax highlighting, line numbers and undo per block. Every keystroke is saved immediately. If feature code changes elsewhere — a glyph rename rewrites it, or Time Machine restores it — the editor updates to match.

Validation

Validation compiles your blocks exactly as export would, including the kerning and mark code Ink generates. It runs when the tab opens and whenever you press Validate — not while you type.

  • The strip under the editor reads “No diagnostics” or a count of errors and warnings.
  • After you edit code, add or delete blocks, or change kerning or glyphs, it shows Out of date and dims the old results. Press Validate again. Anchor edits don't mark it out of date, so validate after changing anchors too.
  • Each diagnostic shows its block and line. Click it to jump there; problems are also marked in the editor's margin.
  • Variable syntax — values such as (wght=400:10 wght=900:50), conditionset and variation — compiles in variable fonts. A static font reports an error on that line.

Automatic features

On OTF and TTF export Ink generates kern (and dist) from your kerning, and curs, mark, mkmk, abvm and blwm from your anchors. A # Automatic Code line inside your own block for one of those tags marks where the generated code goes: code above it runs first, code below it after.

Your block for the tagResult
NoneGenerated code goes in its default place.
One # Automatic Code lineThe line is replaced by the generated code.
mark, mkmk, abvm or blwm without the lineYour block replaces the generated one.
curs without the lineGenerated code comes before yours.
kern without the lineGenerated kerning comes after yours.
More than one marker, or a kern marker inside lookup { }Compile error.

Export per format

OTF / TTFBlocks are assembled in order with the generated code and compiled. Disabled blocks are left out.
UFO / designspaceWritten to features.fea. Disabled blocks are written commented out with a # disabled line. Generated kern and mark code isn't written — kerning and anchors are exported as data.
.glyphsWritten as features, prefixes and classes, keeping the disabled flag. Glyphs uses its own syntax for variable values, so variable code may not compile there.

Compiled fonts

A font opened directly as OTF, TTF or WOFF is read-only here. Instead of an editor the tab summarises its GSUB and GPOS features, lookups and script systems, its GDEF classes and any warnings. Choose File → Export → Export as .ink… and Ink converts the lookups back into editable code — they appear as prefix blocks, in their original order.

Good to know
  • Blocks can't yet be reordered, renamed or disabled from this tab.
  • All languagesystem statements are moved to the top at export, so export can accept a placement that Validate flags.
  • Feature code is captured by Time Machine.
